## 本版要点

这一版只做一件事：**解决「切到桌面就断播」**。全屏看片时回消息、看别的 App，
画面不再消失，而是缩成小窗继续播。

### 新增：画中画

以前全屏播放时切回桌面，画面跟着消失、声音却还在响 —— 这是系统的默认行为，
不是播放器没停。现在播放页接入了系统画中画：

| 操作 | 效果 |
| --- | --- |
| 全屏播放中切回桌面 / 打开别的 App | 播放窗口自动缩成小窗，**声音画面都不中断** |
| 按住小窗拖动 | 可放到屏幕任意角落，贴边也不会被裁掉 |
| 点小窗最大化按钮 | 恢复全屏播放，**接着原来的进度继续**，不会从头播 |
| 点小窗关闭按钮 | 停止播放并保存进度，下次打开接着看 |

**适用范围**：点播和直播都支持。直播切小窗后画面照常跟着播，不会卡在切走那一帧。

**找不到按钮怎么办**：小窗上的拖动、最大化、关闭都是系统自带的手势和按钮，
不依赖应用内的控制条 —— 即使控制条已经自动隐藏，小窗照样能拖、能还原。

### 连带改顺的几处

画中画不是一个开关，它跟后台策略、播放器重建、进度记录三件事绑在一起，
所以顺手把这几个地方也理顺了：

- **退后台留了 1.2 秒宽限**：误触 Home 键、或者下拉通知栏马上又收回去，
  不会闪一下暂停图标再继续。真的退到后台、1.2 秒后仍未进小窗，才暂停并保存进度。
- **从小窗回来不重建播放器**：只把新的画面 Surface 换给现有播放器实例，
  配合持续记录的播放位置，才能做到"接着原来的进度"。重建实例会黑屏一下、
  还可能被服务端当成新会话从头推流。
- **设备不支持时自动降级**：个别定制系统会在策略层禁掉画中画，此时不会弹错误，
  而是退回旧行为 —— 退后台即暂停并保存进度，回来从原位置继续。

### 实现要点（给想改代码的人）

- 传给 `PiPWindow.create()` 的 `componentController` 必须是被播视频**正显示着的**那个
  `XComponent` 的控制器，且 `XComponent` 的 `type` 得是 `SURFACE`。
  因此把 XComponent 的控制器改成由页面持有，再往下传。
- 用 `Navigation` 管路由时，配置里的 `navigationId` **必须等于** Navigation 组件的 `.id()`，
  否则从画中画恢复时会回错页面。为此把 Navigation 的 id 抽成了常量。
- `setAutoStartEnabled(true)` 才是「主窗退后台自动转小窗」的开关。
  不设它，就是老行为：画面挂在后台、声音照放。
- 必须在 `XComponent` 的 `onLoad` 之后才能 `create()`，
  否则拿不到有效 Surface，小窗创建出来是黑的。
- 小窗状态变化和按钮事件的回调语义在不同系统版本上不一致，
  最终按 `player.isPlaying()` 的实际状态取反来驱动按钮图标，不依赖回调里的 `status` 字段。

## 环境要求

- HarmonyOS NEXT / OpenHarmony，**API 26 及以上**
- 应用**不内置任何片源**，首次使用需自行在「我的 → 视频源管理」添加点播源（Apple CMS V10）与直播源（M3U / TXT）

## 已知问题

- 只支持 Apple CMS V10 点播接口与 M3U/TXT 直播订阅；TVBox 的 `type:3` 蜘蛛源不能当点播源使用
- 自动换源依赖「同名影片能搜到」：标题带季集号、译名差异较大时可能找不到备用源，
  此时会退回手动换源提示
- 离线缓存是把 HLS 分片按字节拼接成单个 `.ts`。**若源站各分片的时间戳不连续**，
  个别影片仍可能在中途出现一次短暂停顿（本地自愈会尝试重新同步，但不保证一定成功）。
  这类片源建议在线观看
- 画中画依赖系统能力，个别定制 ROM 上若被系统策略禁用，会自动退回「退后台即暂停」的旧行为
- 网盘 / 磁力播放尚未实现
